## 1.11a natijasi (Tech Lead to'ldiradi)
- **`ErrorCode.REFRESH_SUPERSEDED`** (401, faqat `POST /auth/refresh`): grace oynasida (`REFRESH_REUSE_GRACE_SECONDS`, dev 30 s) almashtirilgan token kelganda. Oila bekor qilinmaydi, cookie tozalanmaydi — frontend logout QILMASIN: boshqa tab yangi `rt` cookie yozgan bo'ladi, qisqa kutib (yoki Web Locks bilan) refresh'ni bir marta qayta urinsin. Faqat oddiy `UNAUTHORIZED` da logout.
- **`POST /auth/logout`** endi `X-Requested-With: XMLHttpRequest` siz 403 (api client hamma so'rovga qo'yadi — tasdiqla).
- **Strict sxemalar:** login, change-password, parent exchange, parent-tokens create body'sida ortiqcha maydon → 400. `changePasswordFormSchema.confirmPassword` serverga yuborilmasin.
- **UUID xatosi:** `VALIDATION_ERROR` + `details[]` (avval `BAD_REQUEST`).
- **Change-password limiti:** user id bo'yicha 5 xato / 15 daqiqa → 429 `TOO_MANY_REQUESTS` (yoki `ErrorCode` dagi mos kod) — formada umumiy xabar ko'rsatilsin.
- **H3 backend:** cookie bilan muvaffaqiyatli body'siz exchange endi limitga sanalmaydi, lekin frontend baribir avval `GET /auth/me` chaqirsin (docs/02 §5.1).
- **Helmet (API):** API javoblarida CSP `default-src 'none'` — bu faqat JSON javoblarga tegishli, web sahifalarga ta'sir qilmaydi.
- **Web konfiguratsiya:** `apps/web/next-env.d.ts` endi `.gitignore` da va `lint`/`typecheck` skriptlari `next typegen && ...` bilan boshlanadi; `tsconfig.json` `include` da `.next-e2e/types/**/*.ts` va `.next-be/types/**/*.ts` bor — build'dan keyin ishchi daraxt toza qolishi kerak (o'z distDir'ing uchun shu ikkisidan birini ishlat, masalan `NEXT_DIST_DIR=.next-be`).
- **postcss override:** `pnpm-workspace.yaml` da `next>postcss: 8.5.32` (pnpm audit high zaiflik uchun).
