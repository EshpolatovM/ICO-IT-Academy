## Aniq vazifa (backend)
1. **H1:** login (staff + student) va parent exchange rate limit — urinish parol/token tekshiruvidan OLDIN atomar hisoblansin (`INCR` → limitdan oshsa 429). Login muvaffaqiyatli bo'lsa `ip+login` hisoblagichi reset. Qo'shimcha: IP bo'yicha umumiy login limiti (password spraying / Argon2 CPU DoS'ga qarshi) — raqamlar env/config'da (`LOGIN_IP_RATE_LIMIT_MAX_ATTEMPTS`, `..._WINDOW_SECONDS`; dev qiymatlarini mantiqiy tanla, masalan 50/15 daqiqa, `.env.example` va lokal `.env` ga qo'sh). E2E: parallel N so'rov → limitdan ortig'i 429.
2. **H2 (backend):** refresh reuse grace oynasi — `REFRESH_REUSE_GRACE_SECONDS` (env, masalan 30). Almashtirilgan (`replaced_by_id` bor) token grace ichida qayta kelsa: oila bekor QILINMAYDI, 401 yangi `ErrorCode.REFRESH_SUPERSEDED` (`@lms/shared`), cookie tozalanmaydi. Grace'dan keyin — hozirgidek reuse → oila bekor. Unit + e2e.
3. **H3 (backend):** body'siz exchange'da cookie (AES-GCM bilan autentifikatsiyalangan, ya'ni server o'zi bergan) tokenlari bilan MUVAFFAQIYATLI exchange IP urinish limitiga sanalmasin; muvaffaqiyatsizlari (revoked/expired) — sanalsin. Body bilan kelgan tokenlar — hozirgidek sanaladi.
4. **H4:** deny-by-default — `RolesGuard`: `@Public`, `@Roles(...)` yoki yangi `@AnyAuthenticated()` dekoratorlaridan birortasi bo'lmasa → 403. Hozirgi "ANY" endpointlar (`/auth/me`, `/auth/logout`, `/auth/sessions*`, `/auth/change-password` — docs/12 §1 ga qarab) ga to'g'ri dekorator. Test: Nest `DiscoveryService`/`Reflector` orqali BARCHA route'larni aylanib, har birida shu uch metadata'dan biri borligini tekshiruvchi unit/e2e test (yangi endpoint unutilsa CI yiqiladi).
5. **H5 (api):** `helmet` (aniq pin, ≥2 hafta oldin chiqqan stable) `configureApp` da: `noSniff`, `frameguard: deny`, `referrerPolicy: no-referrer`, HSTS faqat `NODE_ENV=production`, CSP API uchun `default-src 'none'; frame-ancestors 'none'` (JSON API). E2E: header'lar bor.
6. **M1:** `RedisService.incrementWithTtl` atomar — `MULTI` (`INCR` + `EXPIRE key ttl NX`) yoki Lua. Unit.
7. **M2:** `token_version` — versiya o'zgarganda kesh xatosi yutilmaydi (DEL, xato yuqoriga) yoki kamida xato bo'lsa DEL qayta urinish; keshga yozish "faqat kattaroq versiya" (Lua compare-and-set). Unit.
8. **M3:** `change-password` — user id bo'yicha muvaffaqiyatsiz eski parol urinishlari limiti (`FixedWindowRateLimiter`, env: `CHANGE_PASSWORD_RATE_LIMIT_*`). E2E: limitdan keyin 429.
9. **M4 + L5:** parent token revoke/regenerate — keshni tozalashdan oldin yoki u bilan birga audit; Redis xatosi revoke'ni 500 ga aylantirmasin (log + davom), poygaga qarshi `revoked` tombstone (qisqa TTL, kalit/TTL konstanta) — validity tekshiruvi tombstone'ni ko'rsa DB'ga qaramay rad etadi. Audit'ni imkon bo'lsa asosiy amal tranzaksiyasiga kirit (password-reset va parent token'da); bo'lmasa sababini yoz.
10. **M5:** production'da (`NODE_ENV=production`) `change_me` bilan boshlanadigan yoki `.env.example` dagi qiymatga teng sirlar (`JWT_ACCESS_SECRET`, `PARENT_TOKEN_PEPPER`, `PARENT_COOKIE_KEY`, DB/Redis/S3 parollari ham bo'lsa) rad etilsin. Unit.
11. **L1:** `POST /auth/logout` ga `CsrfHeaderGuard`. **L2:** access JWT'ga `aud` (masalan `access`) va tekshiruv; parent session `aud` bilan aralashmasin. **L3:** BaseRepository'dan meros olmagan repository'larga sababi izohi. **L7:** auth va parent request sxemalari `z.strictObject` (noma'lum maydon → 400). **L8:** CI'ga `pnpm audit --audit-level high` qadami (o'tmasa — hisobotda ayt, `--prod` bilan cheklash mumkin). **L10:** README "Reverse proxy" bo'limiga zanjir misoli (Nginx → Next → API: hop soni yoki Nginx IP).
12. Frontend uchun o'zgarishlar (yangi `ErrorCode.REFRESH_SUPERSEDED`, logout CSRF header, strict sxemalar) — hisobotda aniq yoz; frontendni O'ZGARTIRMA (1.11b da birchka-frontend qiladi).
