## 4. Biznes qoidalari va invariantlar

### 4.1 Enrollment — tanlov: **lazy (birinchi murojaatda)**
`/student/*` dagi har bir chaqiruv `StudentPathResolver` → `PathEnrollmentService.ensure(studentId, pathId)` dan boshlanadi:
1. Joriy yo'l = faol a'zolikdagi (`left_at IS NULL`, guruh o'chirilmagan) guruhning `path_id`. Guruh `ARCHIVED` bo'lsa ham a'zolik faol — yo'l saqlanadi (§11 T-4). Faol guruh yo'q yoki yo'l `PUBLISHED` emas → "yo'l yo'q" (xarita — bo'sh javob, boshqa endpointlar — 404).
2. `UnitOfWork` ichida: `student_path_enrollments` ga `ON CONFLICT DO NOTHING` + zanjirning birinchi ko'rinadigan mavzusi uchun `topic_progress` `AVAILABLE` (`ON CONFLICT DO NOTHING`). Ikkalasi idempotent, parallel so'rovlarda ham bitta qator.
3. Tez yo'l: enrollment allaqachon bor bo'lsa (kesh hit yoki bitta `SELECT`) — yozuv yo'q.

**Nega eager (guruhga qo'shilganda) emas:**
- Backfill yo'q (TL Q-5) — 2-modulda guruhga qo'shilgan mavjud studentlar uchun baribir lazy yo'l kerak bo'lardi; ikki mexanizm o'rniga bitta.
- 2.3/2.2 dagi 3 ta yozish nuqtasiga (`GroupMembersService.add`, `GroupEnrollmentService.enroll`, `enrollNewStudents` — yaratish va CSV import) tegilmaydi; `groups` → `learning` bog'liqligi va aylanma import yo'q.
- Yo'l `DRAFT` paytida guruhga qo'shilib, keyin nashr qilingan holat avtomatik ishlaydi (eager'da birinchi mavzu qatori yo'l nashr qilinganda qayta yozilishi kerak bo'lardi).
- Student boshqa yo'lli guruhga o'tsa (avval chiqarish, keyin qo'shish), yangi yo'l enrollment'i birinchi kirishda paydo bo'ladi; eski enrollment va progress tarix sifatida qoladi (3.1 §2.8).
- Kamchilik: `started_at` — guruhga qo'shilgan sana emas, birinchi kirish sanasi; hisobotlar "yo'lga yozilgan, lekin hali kirmagan" studentlarni `group_members` orqali ko'radi. Ota-ona paneli (14-modul) progressni hisoblaganda enrollment bo'lmasa — "0%" (qator yo'q = boshlanmagan).

### 4.2 Ko'rinadigan zanjir
- Zanjir = ko'rinadigan bo'limlar (`section.order`) ichidagi ko'rinadigan mavzular (`topic.order`), bitta chiziqli ro'yxat (docs/05 §1).
- Kamida bitta ko'rinadigan darsi bo'lmagan mavzu zanjirga **kirmaydi** (aks holda uni yakunlab bo'lmaydi va zanjir to'xtab qoladi) (§11 T-2).
- Ko'rinadigan mavzusi yo'q bo'lim — xaritada ko'rsatilmaydi.

### 4.3 Ochish algoritmi (mavzu va dars)
Kirish: ko'rinadigan zanjir `T[0..n-1]`, `topic_progress` qatorlari `R` (mavzu → status), `lesson_progress` qatorlari.

```
mavzu holati(T[i]):
  agar R[T[i]] bor           → R[T[i]]          # AVAILABLE / IN_PROGRESS / COMPLETED (yozilgan holat hech qachon pasaymaydi)
  agar i == 0                → AVAILABLE
  agar holat(T[i-1]) == COMPLETED → AVAILABLE   # TL Q-7
  agar ∃ j > i: R[T[j]] ∈ {IN_PROGRESS, COMPLETED} → AVAILABLE   # S-35 (docs/05:38): faqat HAQIQIY progress; AVAILABLE qatori faqat o'zini ochiq tutadi
  aks holda                  → LOCKED           # bazaga yozilmaydi (docs/11:228)

dars holati(L[k] — mavzu T ning ko'rinadigan darslari, order bo'yicha):
  agar holat(T) == LOCKED    → LOCKED
  agar lesson_progress bor   → uning statusi (IN_PROGRESS / COMPLETED)
  agar k == 0                → AVAILABLE
  agar holat(L[k-1]) == COMPLETED → AVAILABLE
  agar ∃ m > k: lesson_progress(L[m]) ∈ {IN_PROGRESS, COMPLETED} → AVAILABLE   # S-35, darslar uchun ham (haqiqiy progress)
  aks holda                  → LOCKED

sandiq holati(C, after_topic = T):
  T ko'rinmaydi              → sandiq ko'rinmaydi (TL Q-1)
  holat(T) == COMPLETED      → READY
  aks holda                  → LOCKED
  (OPENED — 5-modulda chest_openings dan)
```
- **Materializatsiya (D-4 yechimi):** `LOCKED` hech qachon yozilmaydi. `AVAILABLE` qatori ikki joyda yoziladi: (a) enrollment'da birinchi mavzu; (b) mavzu `COMPLETED` bo'lganda zanjirdagi keyingi ko'rinadigan mavzu. Shu tufayli ochilgan mavzu keyin admin tartibni o'zgartirsa yoki oldiga yangi mavzu qo'shsa ham qayta yopilmaydi (S-35 "ochilgan narsa qayta yopilmaydi"). Hisoblangan (qatorsiz) `AVAILABLE` faqat yuqoridagi qoidalardan kelib chiqadi; birinchi `start` uni `IN_PROGRESS` qatoriga aylantiradi.
- **S-35 qoidasining chegarasi (Domla 🔴-1):** "keyingi mavzuda qator bor" sharti faqat `IN_PROGRESS`/`COMPLETED` qatorlarni hisobga oladi. Materiallashtirilgan `AVAILABLE` qatori boshqa mavzularni ochmaydi — aks holda admin `t1` ni (faqat `AVAILABLE` qatorli) oxiriga ko'chirsa, `t2…tN` hammasi ochilib ketardi. Bu holatda: yangi birinchi mavzu `t2` — `AVAILABLE` (`i == 0`), `t3…tN` — `LOCKED`, `t1` — `AVAILABLE` (o'z qatori).
- Sandiq xaritada o'z `after_topic` tugunidan keyin, shu bo'lim `nodes` ida turadi.

### 4.6 `start`
1. `LessonAccessGuardService` → 404/403 (§4.4).
2. Dars allaqachon boshlangan/yakunlangan → idempotent 200 (joriy holat), yozuv yo'q.
3. Yangi dars: `ReviewGate.check(studentId)` → bloklangan bo'lsa 409 `REVIEW_REQUIRED` + `details: ReviewRequiredDetails` (`{ due: [{ topicId, title }] }`, docs/12:323, R Q-5). 3-modulda doim o'tkazadi.
4. `UnitOfWork`: `lesson_progress` `IN_PROGRESS` (`started_at = now()`, `ON CONFLICT DO NOTHING`); `topic_progress` → `IN_PROGRESS` (qator yo'q yoki `AVAILABLE` bo'lsa; `COMPLETED` ga tegilmaydi), `started_at`.
5. Commit'dan keyin `StudentPathCache.invalidate(studentId)` (mavzu holati o'zgargan bo'lishi mumkin).

### 4.7 `complete`
1. Kirish tekshiruvi (§4.4).
2. Dars boshlanmagan bo'lsa — **avval start qoidalari** (§4.6 3-qadam, `ReviewGate` bilan) va shu tranzaksiyada boshlanadi. Sabab: yangi xato kodi qo'shmaslik; min. o'qish vaqti 3-modulda yo'q (§11 S-B1).
3. `UnitOfWork`:
   - `topic_progress`: avval `ensureRow` (`INSERT … ON CONFLICT DO NOTHING`), **keyin** `lockForUpdate` (`SELECT … FOR UPDATE`) — find → create emas (🟡-6); bir mavzudagi ikki darsning parallel `complete` i mavzu yakunlanishini o'tkazib yubormasligi uchun (READ COMMITTED).
   - `lesson_progress`: `IN_PROGRESS → COMPLETED`, `completed_at = now()` (`WHERE status = 'IN_PROGRESS'`). 0 qator → dars allaqachon yakunlangan → **idempotent**: 200, joriy holat, `rewards: []`, hodisa yo'q (`ALREADY_DONE` 409 emas — ikki marta bosish xato emas).
   - `lessons_completed += 1`.
   - `TopicCompletionService.evaluate` (§4.8).
4. Commit'dan keyin: kesh invalidatsiyasi; hodisalar (`lesson.completed`, va o'tish bo'lsa `topic.completed`) (§5).
5. Javob: `lessonStatus`, `topicStatus`, `rewards: []`, `next` (§2.2).

### 4.8 Mavzu va yo'l yakunlanishi (TL Q-6)
- Mavzu `COMPLETED` ⇔ uning **barcha ko'rinadigan** darslari `COMPLETED` va ko'rinadigan darslar soni > 0.
- O'tish faqat bir marta: `markCompleted` `status <> 'COMPLETED'` sharti bilan; 1 qator yangilangandagina `topic.completed` hodisasi chiqadi va keyingi ko'rinadigan mavzuga `AVAILABLE` qatori yoziladi (`ON CONFLICT DO NOTHING`).
- Barcha ko'rinadigan mavzular `COMPLETED` → `student_path_enrollments.completed_at = now()` (`IS NULL` sharti). Keyin yangi mavzu nashr qilinsa — `completed_at` o'zgarmaydi (S-35: yakunlangan narsa qaytmaydi), yangi mavzu `AVAILABLE` bo'ladi (§4.3).
- **Reconcile (kontent o'zgarishi):** admin qolgan yakunlanmagan darslarni yashirsa/arxivlasa, mavzuning barcha ko'rinadigan darslari yakunlangan bo'lib qoladi, lekin `complete` endi chaqirilmaydi — zanjir to'xtab qoladi. Shuning uchun `GET /student/path` xaritani hisoblayotganda "yozilgan holati `COMPLETED` emas, lekin shart bajarilgan" mavzularni topsa, `TopicCompletionService.reconcile` ni `UnitOfWork` ichida chaqiradi (o'sha idempotent `markCompleted` + keyingi `AVAILABLE` + hodisa). Bu GET'dagi yagona yozuv (lazy enrollment bilan birga), oddiy holatda yozuv yo'q.
- `pass_threshold` va savollar natijasi — 4-modul; `TopicCompletionService` da shart bitta metodda (`isTopicSatisfied`) — 4-modulda kengaytiriladi.

### 4.9 `ReviewGate` — kengayish nuqtasi (S-30, 6-modul)
```ts
export abstract class ReviewGate {
  /** Xarita uchun: `{ blocked, dueCount }`. */
  abstract status(studentId: string): Promise<ReviewBlock>;
  /** Yangi (boshlanmagan) darsni boshlashdan oldin; bloklangan bo'lsa `due` ro'yxati. */
  abstract check(studentId: string): Promise<ReviewGateResult>;
}
```
- 3-modulda `PassThroughReviewGate`: `{ blocked: false, dueCount: 0 }`, `check` — doim ruxsat. Provider `LearningModule` da `{ provide: ReviewGate, useClass: PassThroughReviewGate }` — 6-modul faqat `useClass` ni almashtiradi.
- Gate faqat **yangi** dars boshlashda qo'llanadi (boshlangan darsni tugatish mumkin — docs/05 §2.2).
