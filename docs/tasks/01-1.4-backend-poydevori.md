## Aniq vazifa
1. **Config:** `ConfigModule` (global) + env validatsiyasi **zod** bilan (sxema bitta faylda, noto'g'ri env'da ilova tushunarli xato bilan ishga tushmaydi). Typed config servis/token orqali — kodda `process.env` to'g'ridan-to'g'ri faqat config qatlamida. `main.ts` dagi `API_PORT` ham shu orqali.
2. **Prisma:** `src/infra/prisma/` — `PrismaService` (`PrismaPg` adapter, `onModuleInit/onModuleDestroy`), `PrismaModule` (global). Soft delete: Prisma client extension — `users` (va kelajakda `deleted_at` bor modellar) uchun `find*`/`count` da `deleted_at IS NULL` avtomatik; aniq o'chirilganlarni ko'rish kerak bo'lsa ochiq usul. Qaysi modellarda ishlashi bitta konfiguratsiyada.
3. **BaseRepository:** `src/common/repository/` (yoki docs/13 §3 ga mos joy) — abstract generic class: `findById`, `findMany` + pagination (`page`, `limit`, `total` — limit va default qiymatlar nomlangan konstantalarda; pagination tiplari/zod sxemasi `@lms/shared` da), `create`, `update`, `softDelete` (faqat soft delete'li modellarda). Interfeys orqali. Hozircha bitta haqiqiy repository shart emas, lekin unit test uchun test-double repository bilan ishlashi ko'rsatilsin.
4. **Redis:** `src/infra/redis/` — `RedisModule` (global), `ioredis` (yoki asoslangan tanlov), `REDIS_URL` config'dan, graceful shutdown. Faqat ulanish va oddiy wrapper; kesh strategiyalari keyin.
5. **Xatolar:** global exception filter — har qanday xato docs/12 §0 formatida: `{ "error": { "code", "message", "details" } }`. Domen xatolari uchun base class (`AppException` + `code`), `HttpException`, validatsiya xatolari (400, `details` da maydonlar), Prisma xatolari (unique → 409, not found → 404), noma'lum → 500 (ichki tafsilot javobga chiqmaydi, logga yoziladi). Xato kodlari `@lms/shared` da (front ham ishlatadi).
6. **Validatsiya:** global pipe — DTO'lar zod sxemalari orqali (`@lms/shared` dagi sxemalar; `nestjs-zod` yoki o'z kichik `ZodValidationPipe` — asosla). CLAUDE.md: "Validatsiya DTO orqali".
7. **Logger:** pino (`nestjs-pino`), JSON, har so'rovda `requestId` (kiruvchi `x-request-id` bo'lsa shuni, bo'lmasa generatsiya; javob sarlavhasiga ham qo'yiladi), redact: `authorization`, `cookie`, `password*`, `token*`. Dev'da `pino-pretty` ixtiyoriy.
8. **Health:** `GET /api/v1/health` — `@nestjs/terminus` (yoki oddiy) bilan DB va Redis tekshiruvi. Controller → Service qatlami saqlansin (controller'da logika yo'q).
9. **DRY ko'chirish:** `apps/api/prisma/seed/lib/` dagi umumiy logika:
   - parol siyosati va telefon (E.164) **zod sxemalari** → `@lms/shared` (front ham ishlatadi);
   - parol hash (Argon2id) → `src/common/security/` (yoki mos joy) dagi `PasswordHasher` servis/class (interfeys bilan);
   - `nextStudentCode` → `src/modules/users/` yoki infra'dagi kichik repository/servis (docs/13 §3 ga qarab);
   - seed/CLI shu yangi joylardan import qiladi, `seed/lib` da takror qolmaydi. depcruise qoidalari buzilmasin (kerak bo'lsa `prisma/seed/**` uchun aniq qoida qo'sh va asosla).
10. **Testlar:** har bir yangi servis/class uchun unit test (exception filter barcha tarmoqlari, zod pipe, config validatsiyasi, BaseRepository pagination, PasswordHasher, soft delete extension mantig'i). Health endpoint uchun e2e test (Supertest; DB/Redis — compose'dagi yoki Testcontainers, asosla). Testlar `pnpm test` da ishlaydi.
