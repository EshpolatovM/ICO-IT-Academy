### 2.4 Xato kodlari
Yangi `ErrorCode` qo'shilmaydi (docs/12 §0 ro'yxati). 409 lar — `CONFLICT` + **obyekt** `details` (B-1). Kontent 409 lari — `details: ContentConflictDetails` (`@lms/shared`, `reason` bo'yicha diskriminatsiyalangan union):

| `details` | Qachon |
|---|---|
| `{ reason: "PATH_IN_USE", groupsCount: number }` | Yo'lni guruh(lar) ishlatadi (o'chirilmagan guruhlar soni, `0` bo'lishi mumkin) yoki enrollment/progress bor — arxivlash taklif qilinadi. `groupsCount` doim bor |
| `{ reason: "HAS_PROGRESS" }` | Bo'lim/mavzu/darsda (ichidagilarda) `lesson_progress`/`topic_progress` bor — `ARCHIVED` qilish kerak |
| `{ reason: "HAS_CHEST", chestId: string }` | Mavzuga sandiq bog'langan — avval sandiqni o'chirish yoki boshqa mavzuga bog'lash |
| `{ reason: "CHEST_EXISTS", chestId: string }` | Shu mavzudan keyin sandiq allaqachon bor (`uq_path_chests_after_topic_id`); `chestId` — mavjud sandiq |

```ts
// packages/shared/src/content/content-errors.ts
export const ContentConflictReason = { PATH_IN_USE: 'PATH_IN_USE', HAS_PROGRESS: 'HAS_PROGRESS', HAS_CHEST: 'HAS_CHEST', CHEST_EXISTS: 'CHEST_EXISTS' } as const;
export type ContentConflictDetails =
  | { reason: 'PATH_IN_USE'; groupsCount: number }
  | { reason: 'HAS_PROGRESS' }
  | { reason: 'HAS_CHEST' | 'CHEST_EXISTS'; chestId: string };
/** Unikallik 409 (telefon, slug, ko'nikma nomi) — `admin-users.errors.ts` bilan bir xil shakl. */
export interface ConflictFieldDetails { field: string }
```
`ConflictFieldDetails` umumiy — `packages/shared/src/errors/` ga qo'yiladi (2.2 dagi `phone` ham shu tipga o'tadi, faqat tip — xatti-harakat o'zgarmaydi).

Unikallik maydonlari (`slug`, `skills.name`) — 409 `CONFLICT`, `details: { field: "slug" | "name" }` (obyekt; 2.2 dagi telefon band naqshi, `admin-users.errors.ts:10`). Frontend mavjud `conflictField` bilan o'qiydi. Idempotent: hech narsa o'zgarmasa — 200, audit va versiya bump yo'q. Yo'l allaqachon `PUBLISHED`, lekin `cascade: true` va `DRAFT` bolalar bor — faqat bolalar yangilanadi |

| `SectionsService`, `TopicsService`, `LessonsService` | Yaratish (oxiriga), PATCH, o'chirish (progress tekshiruvi bilan) |

| `ChestsService` | Sandiq CRUD, `afterTopic ∈ section` tekshiruvi, `CHEST_EXISTS` |
| `SkillsService` | Ko'nikma CRUD, ro'yxat |
| `TopicSkillsService` | `PUT /admin/topics/:id/skills` (to'plamni almashtirish) |

## 4. Biznes qoidalari va invariantlar

1. **Status (TL Q-1, R Q-3, R Q-8).** Yangi yaratilgan har bir daraja `DRAFT`. Barcha darajalar (yo'l ham) statusi `PATCH` (`status`) bilan istalgan qiymatga o'zgaradi; yo'l uchun qo'shimcha `POST …/publish`. Yagona kaskad — `publish` `{ cascade: true }`: faqat `DRAFT → PUBLISHED`, faqat pastga. Boshqa hech qaysi o'zgarish (arxivlash, `DRAFT` ga qaytarish, bo'lim/mavzu PATCH) ota yoki bolalarga tarqalmaydi. Nashr uchun oldindan shart yo'q (bo'sh yo'lni ham nashr qilish mumkin — student bo'sh xaritani ko'radi, §9 T-3).
2. **Student ko'rinishi** (3.3 da hisoblanadi, bu yerda faqat hujjat): yo'l ∧ bo'lim ∧ mavzu ∧ dars `PUBLISHED`. Sandiq — `after_topic` ko'rinsa.
3. **Ko'chirish yo'q (TL Q-2).** `PATCH` sxemalarida `sectionId`/`topicId` yo'q (`strictObject` → 400).
4. **Sandiq.** `afterTopicId` mavzusi shu sandiqning `section_id` bo'limiga tegishli bo'lishi shart (yaratish va PATCH). Bitta mavzudan keyin bitta sandiq. `reward` faqat saqlanadi — hech narsa berilmaydi (5-modul).
5. **Tartib (TL Q-3).** Yaratish — oxiriga. `PUT …/order` ro'yxati parent'ning **barcha** bolalari (barcha statuslar) ning aniq permutatsiyasi bo'lishi shart. Natija `order = 1…n`. O'chirishdan keyin bo'shliq qolishi mumkin (qayta raqamlanmaydi; tartib faqat taqqoslash uchun).
6. **O'chirish (3.1 §2: soft delete yo'q).**
   - Yo'l: guruh ishlatsa yoki enrollment/progress bo'lsa — 409 `PATH_IN_USE`. Aks holda kaskad.
   - Bo'lim/mavzu/dars: ichida biror `lesson_progress`/`topic_progress` bo'lsa — 409 `HAS_PROGRESS` (yo'li: `ARCHIVED`). Aks holda kaskad (bo'lim → mavzular, darslar, sandiqlar, `topic_skills`).
   - Mavzu: sandiq bog'langan bo'lsa — 409 `HAS_CHEST` (`NoAction`). Bo'lim butunlay o'chirilganda bu tekshiruv qo'llanmaydi (kaskad, 3.1 §2.5).
   - Ko'nikma: `topic_skills` kaskad (portfolio bog'lanishlari 7-modulda).
   - Sandiq: 3-modulda `chest_openings` yo'q — erkin o'chadi.
7. **Slug.** `PATH_SLUG_PATTERN` (`^[a-z0-9]+(?:-[a-z0-9]+)*$`), unique (`uq_learning_paths_slug`) → 409 `field: slug`.
8. **Kontent xavfsizligi.** `contentMd` xom Markdown sifatida saqlanadi; HTML tozalash frontend renderer'da (03-reja: HTML o'chiriladi). `videoUrl` — faqat `https:` sxemasi (`LESSON_VIDEO_URL_PROTOCOLS`; `http:`, `javascript:` va h.k. — 400). Video 3-modulda faqat havola, embed yo'q (R Q-10). JSON body limiti (`main.ts`) `LESSON_CONTENT_MAX_LENGTH` ni sig'dirishini tekshir; o'zgartirish kerak bo'lsa — to'xta va hisobot ber.
9. **S-35.** Nashr qilingan kontentni tahrirlash progressga tegmaydi: versiyalash yo'q, progress qatorlari o'chirilmaydi (`Restrict`). O'rtaga mavzu/dars qo'shish va tartib o'zgarishining studentga ta'siri — 3.3 §4.
