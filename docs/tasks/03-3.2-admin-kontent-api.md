### 2.2 So'rov shakllari (asosiylari)
- `CreatePathRequest`: `{ title (1–128), slug (kebab-case, 1–128), description? (≤ PATH_DESCRIPTION_MAX) }`. `status` yozilmaydi — servis `DRAFT` qo'yadi. `coverFileId` 3-modulda **yo'q** (fayl yuklash moduli hali yo'q, §9 T-6).
- `UpdatePathRequest`: `{ title?, slug?, description?: string|null, status?: DRAFT|ARCHIVED }` (kamida bittasi, `hasAnyField`). `PUBLISHED` faqat `POST …/publish` orqali.
- `CreateSectionRequest`: `{ title (1–128), description? }` → oxiriga qo'shiladi (`order = max + 1`), `DRAFT`.
- `UpdateSectionRequest`: `{ title?, description?: string|null, status?: ContentStatus }`.
- `CreateTopicRequest`: `{ title (1–128), description?, icon? (≤64) }`; `UpdateTopicRequest`: `{ title?, description?, icon?, status? }`. `sectionId` yo'q (Q-2).
- `CreateLessonRequest`: `{ title (1–128), contentMd? (default ''), videoUrl? (http/https, ≤512), estMinutes? (1…LESSON_EST_MINUTES_MAX) }`; `UpdateLessonRequest`: shu maydonlar ixtiyoriy + `status?`, `videoUrl/estMinutes` uchun `null` — tozalash. `topicId` yo'q.
- `CreateChestRequest`: `{ title (1–64), afterTopicId: uuid, reward: ChestReward }`; `UpdateChestRequest`: `{ title?, afterTopicId?, reward? }`.
- `ChestReward` (docs/11:214 shakli, D-2): `{ xp: { min, max }, coin: { min, max } }` — butun son, `≥ 0`, `min ≤ max` (`refine`, xato `field: reward.xp.max`). Qat'iy qiymat — `min = max`.
- `CreateSkillRequest`: `{ name (1–64, trim), icon? (≤64) }`; `UpdateSkillRequest` — ixtiyoriy, kamida bittasi.
- Tartiblash: `{ sectionIds | topicIds | lessonIds: uuid[] }` — takrorsiz (`refine`), 1…`CONTENT_REORDER_MAX` ta.
- `{ skillIds: uuid[] }` — takrorsiz, 0…`TOPIC_SKILLS_MAX` (bo'sh massiv — hammasini olib tashlash).

## 4. Biznes qoidalari va invariantlar

1. **Status (Q-1).** Yangi yaratilgan har bir daraja `DRAFT`. Bo'lim/mavzu/dars statusi `PATCH` (`status`) bilan istalgan qiymatga o'zgaradi; yo'l — `POST …/publish` (`PUBLISHED`) va `PATCH` (`DRAFT|ARCHIVED`). Hech qaysi o'zgarish ota yoki bolalarga tarqalmaydi. Nashr uchun oldindan shart yo'q (bo'sh yo'lni ham nashr qilish mumkin — student bo'sh xaritani ko'radi, §9 T-3).
2. **Student ko'rinishi** (3.3 da hisoblanadi, bu yerda faqat hujjat): yo'l ∧ bo'lim ∧ mavzu ∧ dars `PUBLISHED`. Sandiq — `after_topic` ko'rinsa.
3. **Ko'chirish yo'q (Q-2).** `PATCH` sxemalarida `sectionId`/`topicId` yo'q (`strictObject` → 400).
4. **Sandiq.** `afterTopicId` mavzusi shu sandiqning `section_id` bo'limiga tegishli bo'lishi shart (yaratish va PATCH). Bitta mavzudan keyin bitta sandiq. `reward` faqat saqlanadi — hech narsa berilmaydi (5-modul).
5. **Tartib (Q-3).** Yaratish — oxiriga. `PUT …/order` ro'yxati parent'ning **barcha** bolalari (barcha statuslar) ning aniq permutatsiyasi bo'lishi shart. Natija `order = 1…n`. O'chirishdan keyin bo'shliq qolishi mumkin (qayta raqamlanmaydi; tartib faqat taqqoslash uchun).
6. **O'chirish (3.1 §2: soft delete yo'q).**
   - Yo'l: guruh ishlatsa yoki enrollment/progress bo'lsa — 409 `PATH_IN_USE`. Aks holda kaskad.
   - Bo'lim/mavzu/dars: ichida biror `lesson_progress`/`topic_progress` bo'lsa — 409 `HAS_PROGRESS` (yo'li: `ARCHIVED`). Aks holda kaskad (bo'lim → mavzular, darslar, sandiqlar, `topic_skills`).
   - Mavzu: sandiq bog'langan bo'lsa — 409 `HAS_CHEST` (`NoAction`). Bo'lim butunlay o'chirilganda bu tekshiruv qo'llanmaydi (kaskad, 3.1 §2.5).
   - Ko'nikma: `topic_skills` kaskad (portfolio bog'lanishlari 7-modulda).
   - Sandiq: 3-modulda `chest_openings` yo'q — erkin o'chadi.
7. **Slug.** `PATH_SLUG_PATTERN` (`^[a-z0-9]+(?:-[a-z0-9]+)*$`), unique (`uq_learning_paths_slug`) → 409 `field: slug`.
8. **Kontent xavfsizligi.** `contentMd` xom Markdown sifatida saqlanadi; HTML tozalash frontend renderer'da (03-reja: HTML o'chiriladi). `videoUrl` — faqat `http:`/`https:` sxemasi (`javascript:` va h.k. — 400). JSON body limiti (`main.ts`) `LESSON_CONTENT_MAX_LENGTH` ni sig'dirishini tekshir; o'zgartirish kerak bo'lsa — to'xta va hisobot ber.
9. **S-35.** Nashr qilingan kontentni tahrirlash progressga tegmaydi: versiyalash yo'q, progress qatorlari o'chirilmaydi (`Restrict`). O'rtaga mavzu/dars qo'shish va tartib o'zgarishining studentga ta'siri — 3.3 §4.

- Mentor: faqat `GET /admin/paths` va `GET /admin/paths/:id/tree` (docs/12 §3, Q18 / M4). Yozish endpointlarida mentor — 403. `GET /admin/paths/:id`, `GET /admin/lessons/:id`, `GET /admin/skills` — mentor uchun **yopiq** (docs/12 §3 jadvali; docs/01 bilan farqi — §9 S-C1). - Student, ota-ona: barcha `/admin/*` — 403 (ota-ona — `ParentReadOnlyGuard`/`RolesGuard`).

## 7. Audit
docs/01 §4 da kontent amallari sanalmagan; nashr va o'chirish studentlarga bevosita ta'sir qiladi, shuning uchun yoziladi (§9 T-7). Yozuv mutatsiya bilan bitta tranzaksiyada.

| `AuditAction` | Qachon | `before` / `after` |
|---|---|---|
| `CONTENT_CREATED` | Yo'l, bo'lim, mavzu, dars, sandiq, ko'nikma yaratildi | `after`: `{ title/name, parentId }` |
| `CONTENT_UPDATED` | PATCH (status'dan tashqari maydonlar) | o'zgargan maydon **nomlari** va qisqa qiymatlar; `contentMd` qiymati yozilmaydi (faqat `changedFields: ["contentMd"]`) |
| `CONTENT_STATUS_CHANGED` | `status` o'zgardi (shu jumladan `publish`) | `{ status }` oldin/keyin |
| `CONTENT_REORDERED` | `PUT …/order` | `{ ids }` oldin/keyin |
| `CONTENT_DELETED` | DELETE | `before`: `{ title/name, parentId }` |
| `TOPIC_SKILLS_SET` | `PUT /admin/topics/:id/skills` | `{ skillIds }` oldin/keyin |

`AuditEntityType`: `LEARNING_PATH`, `PATH_SECTION`, `TOPIC`, `LESSON`, `PATH_CHEST`, `SKILL`. Bitta PATCH ham status, ham boshqa maydon o'zgartirsa — ikkita yozuv. O'zgarishsiz PATCH (no-op) — audit yo'q, versiya oshmaydi.
